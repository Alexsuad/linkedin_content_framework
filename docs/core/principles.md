# Principios Fundamentales del Framework

Estos principios actúan como la constitución operativa del sistema. Ninguna regla o decisión táctica posterior debe contradecir estos enunciados.

---

## 1. Claridad antes que Volumen
La consistencia no se mide en cantidad de posts semanales, sino en la solidez técnica e impacto cualitativo de cada pieza. Es preferible retrasar o cancelar una publicación antes que emitir contenido inmaduro, confuso o genérico por cumplir un calendario.

## 2. Contenido Basado en Fuentes Reales
El contenido debe nacer de fricciones operativas vividas, dudas operativas, fricciones del trabajo diario o aprendizajes reales de proyectos. Se prohíbe generar contenido basado únicamente en abstracciones o tendencias del LLM sin anclaje en el negocio.

## 3. Aprobación Humana Adaptativa
El sistema opera bajo un control de publicación regulado por niveles de autonomía progresiva. Durante la fase de calibración inicial, se requiere una aprobación manual estricta por parte del responsable del perfil editorial. A medida que el sistema madura, el framework admite configuraciones de aprobación compacta por lotes o revisión por excepción, garantizando la trazabilidad y la existencia de gates adaptados a cada nivel de madurez operativa.

## 4. No Inventar Casos ni Resultados
Está terminantemente prohibido falsear testimonios, inventar retornos de inversión (ROI) inexistentes, o simular cuellos de botella que no hayan ocurrido. Los casos y ejemplos se usan para explicar problemas reales y deben presentarse con total honestidad.

## 5. Trazabilidad Operativa
Toda publicación activa debe contar con una traza que identifique la señal de origen (`input/`), el borrador corregido por auditoría, los comentarios del aprobador y, finalmente, el registro de aprendizaje post-publicación.

## 6. Perfiles Editoriales Configurables
El sistema es modular. Toda regla específica sobre el tono de voz, el ritmo semanal, la audiencia objetivo o los formatos debe vivir dentro de un archivo de configuración del perfil editorial, manteniendo el núcleo del framework limpio de detalles particulares de personas o industrias.

## 7. Separación entre Núcleo General y Casos de Uso
El framework madre contiene la lógica organizativa y de control. Las particularidades de sectores industriales (como logística) y cuentas individuales (como Alex) pertenecen a la capa de casos de uso y no deben influir en las reglas generales de gobernanza o arquitectura.
